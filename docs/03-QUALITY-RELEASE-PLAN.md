# Codex Monitor 质量与发布计划

## 1. 质量目标

Codex Monitor 的首要质量是“绝不把授权答错对象，也绝不把过期状态冒充实时状态”。其次是低资源占用、隐私最小化和长时间稳定运行。

发布阻断条件：

- 任何自动审批、跨任务审批、重复审批或未在白名单内的写调用。
- 授权事项被错误清除或错配到其他任务。
- 断线时继续显示“实时在线”。
- 日志或缓存泄露凭据、完整命令或用户未同意保留的任务内容。
- P0/P1 缺陷仍开放。

## 2. 测试分层

| 层级 | 覆盖范围 | 主要负责人 | 自动化要求 |
|---|---|---|---|
| 单元测试 | JSON-RPC 解码、状态归并、外部生命周期新鲜度、去重、排序、脱敏 | Swift / 集成工程师 | 每次提交 |
| 契约测试 | 当前 Codex schema、未知字段、版本退化 | 集成工程师 | 每次合并 |
| 组件测试 | TaskStore、通知、缓存迁移、连接状态机 | Swift 工程师 | 每次合并 |
| 集成测试 | App Server 子进程、握手、托管任务、审批、重连 | 集成 + QA | 每日和发布候选 |
| 端到端测试 | 工作台交办、授权、完成、失败、睡眠恢复 | QA | 里程碑和发布候选 |
| UI 测试 | 菜单栏、窗口、筛选、键盘、VoiceOver | QA / 设计 | 发布候选 |
| 性能测试 | 100/500 任务、事件风暴、8 小时运行 | QA | G3/G4 |
| 安全测试 | RPC 白名单、日志脱敏、恶意文本、配置变更 | 安全评审 | G2/G4 |

## 3. 测试环境

最少维护以下组合：

1. 当前开发环境：macOS 26.3、Xcode 26.2、Codex.app 内置 CLI 0.142.2、shell CLI 0.144.1。
2. 最低支持 macOS 版本。
3. 当前支持的 Codex 前一版本。
4. 未识别的未来版本模拟器，用于验证安全退化。
5. 无 Codex、Codex 路径损坏、App Server 启动失败和审批 schema 不兼容等失败环境。

测试不能依赖用户真实项目或凭据。使用临时测试工作区和可删除的测试任务；任何会触发模型用量的自动化测试必须单独标识并默认关闭。

## 4. 核心测试矩阵

### 4.1 连接与恢复

- [ ] 找到 PATH 中的 Codex 并显示版本。
- [ ] Codex 不存在时给出可操作诊断。
- [ ] App Server 握手成功、失败和超时。
- [ ] JSON 行拆包、半包、多行和非法 JSON。
- [ ] 子进程意外退出后退避重连。
- [ ] Mac 睡眠 5 分钟后恢复并全量同步。
- [ ] Codex 升级或重启后重新检测版本。
- [ ] 重连期间不重复发送已解决通知。

### 4.2 任务与项目

- [ ] 相同 `cwd` 的任务归入同一项目。
- [ ] 符号链接、尾斜杠和同名目录正确处理。
- [ ] 任务标题为空、超长、包含换行或控制字符。
- [ ] 100 个任务和 20 个项目下筛选排序正确。
- [ ] 归档任务默认不出现。
- [ ] 未知 source kind 不导致崩溃。

### 4.3 状态与举手

- [ ] `waitingOnApproval` 创建一个授权举手。
- [ ] 重复 approval 事件不会创建重复事项。
- [ ] 工作台一次允许后 resolved/final 事件正确撤下举手。
- [ ] 工作台拒绝、取消和中断分别显示正确结果。
- [ ] 一个任务并发多个请求时按 request/item id 分离。
- [ ] `turn/completed` 只完成对应 turn。
- [ ] 完成未阅在用户查看后变为已汇报，不修改 Codex。
- [ ] 过期推断状态显示“待核实”。
- [ ] 快照与事件冲突时按时间和权威级别归并。
- [x] 新鲜外部 `task_started` 进入办理中，追加完成事件后进入完成未阅。
- [x] 应用启动后新建的外部会话无需手动刷新，在后台发现周期内进入工作台。
- [x] 后台最近页只新增未知 ID，不删除旧卡、不覆盖既有外部运行态，重复结果幂等。
- [x] 新发现后快速完成的外部会话进入完成未阅；启动前的旧完成仍留在历史。
- [x] 完整校准默认分页到末页并能读取第 201 条，最近页不会继续追踪旧页游标。
- [x] 完整刷新与后台发现单飞；旧连接代次的响应不会合并。
- [x] 未闭合但超过 10 分钟的外部任务不会永久显示办理中。
- [x] 旧失败和旧中止在启动时回到历史，只保留近期异常举手。

### 4.4 通知

- [ ] 新授权即时通知。
- [ ] 10 秒内多个完成任务被聚合。
- [ ] 通知正文在隐私模式下不含路径或命令。
- [ ] 点击通知打开正确任务；任务已解决时显示最新状态。
- [ ] 通知权限被拒绝不影响工作台。
- [ ] 应用重启后不重放旧通知。

### 4.5 审批与安全

- [ ] 所有允许 RPC 都在白名单快照中。
- [ ] 任意字符串 RPC 发送入口不存在。
- [ ] 仅允许定义好的 thread/turn 请求和当前 Server request 响应。
- [ ] shell、fs、config、账户、删除、归档和长期权限方法被测试阻断。
- [ ] request/thread/turn/item/连接代次任一不匹配时禁止响应。
- [ ] 双击、迟到、重复、已 resolved 和断线缓存 request 均不能二次响应。
- [ ] `acceptForSession` 和自动批准入口不存在。
- [ ] 恶意标题不能触发命令、URL 或富文本执行。
- [ ] 环境变量和 auth 信息不进入日志。
- [ ] 应用不读取、创建或修改 `~/.codex/hooks.json`。
- [x] 独立原生任务只能只读观察生命周期；来源标记为 `OBSERVED`，不能生成审批入口。

## 5. 无障碍与视觉 QA

- VoiceOver 焦点顺序：窗口标题 → 摘要 → 项目 → 筛选 → 卡片 → 详情。
- 200% 字体下无核心按钮被截断。
- “增加对比度”下状态边界仍清晰。
- “减少动态效果”下无举手位移动画。
- 仅灰度显示时，授权、失败、完成仍可通过图标和文案区分。
- 键盘可完成筛选、选择项目、打开任务和标为已阅。
- 窗口在最小尺寸、全屏和多显示器切换时不丢失。

## 6. 性能与稳定性测试

### 6.1 数据规模

| 场景 | 数量 | 通过条件 |
|---|---:|---|
| 常规 | 20 tasks / 4 projects | 交互无可感知延迟 |
| 目标上限 | 100 tasks / 20 projects | 过滤排序 < 16 ms，滚动流畅 |
| 压力 | 500 tasks / 50 projects | 不崩溃，可降级显示 |
| 事件风暴 | 1,000 events / 10 s | 无重复通知，最终状态一致 |
| 长稳 | 8 小时 | 无持续内存增长，自动重连有效 |

### 6.2 性能采集

- 使用 Instruments 检查 CPU、内存、泄漏、Swift Concurrency 和卡顿。
- Debug 菜单可导入脱敏事件 fixture，避免性能测试调用真实模型。
- 性能基线存储为版本化报告，不把原始用户任务写入测试资产。

## 7. 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 错误/自动审批、越权调用、数据泄露、破坏用户文件、应用不可启动 | 立即停止发布 |
| P1 | 状态错配、授权误报、持续崩溃、无法重连 | 发布前必须修复 |
| P2 | 主要功能可绕过但体验受损 | 明确负责人和修复版本 |
| P3 | 文案、轻微视觉或非核心兼容问题 | 可进入后续迭代 |

## 8. 发布流程

### 8.1 内部开发版

- Debug 签名。
- 使用模拟事件和临时测试项目。
- 允许显示协议诊断，但默认脱敏。

### 8.2 Alpha

- 仅团队内部。
- 完成 G0、G1、G2。
- 仅启用工作台托管模式；审批必须由用户明确点击。
- 收集本地诊断，不自动上传。

### 8.3 Beta

- 5–10 名目标用户。
- 完成 G3。
- 签名并公证，提供明确卸载说明。
- 崩溃报告必须用户主动同意。

### 8.4 Release Candidate

- 冻结功能，只修 P0/P1。
- 完成 G4、兼容矩阵、隐私检查和 8 小时长稳。
- 校验版本号、更新说明、许可证和安装包签名。

### 8.5 正式发布

- 首期采用 Developer ID 直接分发；App Sandbox 由子进程验证结果决定。
- 发布 SHA-256、变更说明、已知限制和卸载步骤。
- 不安装 Hook，不开放本地网络端口。

## 9. 回滚策略

- 应用版本支持覆盖安装回退到前一稳定版。
- 本地存储迁移先备份旧 schema，失败时进入只读恢复模式。
- 新 Codex 版本不兼容时远端无需开关：应用本地自动退化为快照只读。
- 若发现错误审批或越权调用，立即禁用真实任务入口并发布历史只读修复版。
- 回退版本重启 App Server 前必须把在途任务标为待核实，不能伪造最终状态。

## 10. 本地 Alpha 结果

本地 Alpha 已完成格式检查、26 项单元/协议测试、真实 App Server 只读集成、原生 Codex 状态对账、Release 构建、ad-hoc 签名和原生界面检查。详细证据见 [本地 Alpha 验收记录](./06-LOCAL-ALPHA-ACCEPTANCE.md)。以下检查表仍用于公开发布，不因本地 Alpha 通过而自动完成。
