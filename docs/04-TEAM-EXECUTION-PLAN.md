# Codex Monitor 团队与执行计划

## 1. 交付策略

采用四阶段、五闸门的正常产品开发流程：发现与验证 → 设计与架构 → MVP 开发 → 稳定与发布。架构已经收敛为工作台托管 App Server，后续重点是任务所有权、审批安全和退出恢复。

推荐日历周期为 4 周；如果只有一名全栈 macOS 工程师，则按 6–8 周计划。所有估时以理想工程日计算，不包含等待用户研究和证书审批的时间。

## 2. 团队配置与岗位职责

### 2.1 产品经理（PM）

负责：

- 维护项目章程、范围、优先级和成功指标。
- 组织用户访谈，验证“经理—职员—举手”是否易懂。
- 决定状态语义、通知策略和 v1.0/v1.1 边界。
- 管理里程碑、风险、依赖和验收会议。
- 在技术限制出现时调整范围，而不是要求工程依赖私有接口。

交付物：PRD、验收标准、路线图、评审记录、发布说明。

### 2.2 产品设计师 / UX 设计师

负责：

- 菜单栏、工作台、工作单和设置诊断的交互设计。
- 紧凑职员卡、举手标记、状态层级和空错状态。
- macOS 键盘、窗口、通知和辅助功能规范。
- 制作高保真稿、交互原型和组件规格。
- 与 QA 完成灰度、动态字体、VoiceOver 和减少动态效果验收。

交付物：用户流程、线框、高保真稿、组件表、状态矩阵、可访问性标注。

### 2.3 macOS 客户端工程师（SwiftUI）

负责：

- Xcode 工程、应用生命周期、MenuBarExtra 和主窗口。
- SwiftUI 组件、导航、搜索、筛选、键盘和辅助功能。
- TaskStore、通知、本地缓存和设置界面。
- 睡眠恢复、应用激活、多显示器和性能优化。
- 单元测试、UI 测试和发布构建问题修复。

交付物：可运行应用、UI 组件、状态存储、通知、缓存、测试。

### 2.4 Codex 集成 / 协议工程师

负责：

- App Server 进程宿主、任务所有权和审批归属验证。
- `Process`、stdio、JSON-RPC 握手和重连。
- 版本化协议 DTO、schema fixture 和未知字段兼容。
- thread/item/turn/approval 事件到领域模型的映射。
- Server request 响应、连接代次、幂等和事件顺序。
- RPC 白名单、未知版本退化和退出保护。

交付物：PoC 报告、连接层、协议层、审批协调器、契约测试、兼容矩阵。

### 2.5 QA / 测试工程师

负责：

- 从 PRD 建立测试计划和可追踪用例。
- 构造完成、失败、授权、拒绝、取消、并发和断线场景。
- 运行多版本、多 macOS、长稳、性能和恢复测试。
- 管理缺陷分级、回归和发布候选验收。
- 与设计师共同验证键盘、VoiceOver 和视觉状态。

交付物：测试用例、fixture、缺陷报告、回归报告、发布签字。

### 2.6 安全与隐私工程师

负责：

- 评审 App Server 权限面、RPC 白名单和子进程边界。
- 威胁建模：恶意任务文本、日志泄露、审批错配、重复响应和越权方法。
- 检查脱敏、本地存储、诊断导出和数据清理。
- 审批功能进入真实任务前完成确认界面、最小审计和防重复策略。

交付物：威胁模型、安全评审、隐私清单、发布阻断意见。

### 2.7 构建与发布工程师

负责：

- 构建配置、版本号、签名、公证和产物校验。
- CI 中的单元、契约、UI 和静态检查。
- Alpha/Beta/RC 渠道、更新说明和回滚包。
- 许可证、SHA-256、安装和卸载说明。

交付物：CI、签名安装包、发布检查表、回滚包、变更说明。

### 2.8 技术写作者 / 支持（可由 PM 兼任）

负责：

- 首次启动、任务交办、连接诊断、审批、退出保护、隐私和已知限制文档。
- 把底层 JSON-RPC 错误翻译成用户可操作的说明。
- 维护 FAQ、问题报告模板和诊断包说明。

交付物：用户指南、FAQ、故障排查、支持模板。

## 4. 里程碑与排期

### 阶段 0：发现与技术验证（第 1 周，3–5 个工程日）

目标：完成 G0 证据并冻结 Server 托管边界。

- 记录独立 App Server 无法读取另一实例实时状态的证据。
- 记录当前 daemon 安装前提，确认它不是 MVP 依赖。
- 冻结“工作台创建/接管才实时”的产品范围。
- 产出 Accepted ADR 和兼容矩阵 v0。

退出条件：工程、QA 和安全可以复现结果；产品文档不再包含 Hook 兼容路线。

### 阶段 1：产品设计与工程骨架（第 1–2 周，5 个工程日）

目标：通过 G1、G2。

- 完成菜单栏、主窗口、卡片、工作单和设置诊断高保真稿。
- 建立 Xcode 工程、模块边界、CI 和测试 target。
- 实现协议 fixture 解码、TaskStore 和 RPC 白名单。
- 完成脱敏规则、数据留存和威胁模型。

退出条件：设计评审通过；RPC 与审批边界有自动测试；未知版本能安全退化。

### 阶段 2：MVP 功能开发（第 2–3 周，8–10 个工程日）

目标：完成真实数据闭环。

- App Server 宿主、版本检测、任务创建/接管和事件流。
- 一次性审批、补充信息、退出保护和恢复校准。
- 项目分组、任务状态、注意事项和去重。
- 菜单栏、工作台、详情、搜索筛选和已阅。
- 通知、重连、睡眠恢复、缓存和诊断。
- 单元、契约和主要集成测试同步完成。

退出条件：G3 核心用例通过，无模拟数据依赖。

### 阶段 3：稳定、Beta 与发布（第 4 周，5–7 个工程日）

目标：通过 G4 并发布 Server 托管 MVP。

- 多版本、异常、长稳、性能、无障碍和隐私测试。
- 修复 P0/P1，评审 P2。
- 完成签名、公证、许可证、更新说明和回滚包。
- 5–10 名用户 Beta，验证三秒可读指标。
- 发布 v1.0.0。

退出条件：发布检查表全部完成。

## 5. 正常开发流程

每项功能遵循以下顺序：

1. **需求澄清**：PM 写用户故事、范围和验收条件。
2. **交互设计**：设计师覆盖正常、空、错误、加载、未知和无障碍状态。
3. **技术设计**：工程师说明数据源、状态转换、失败恢复和安全边界。
4. **任务拆分**：拆为 0.5–2 天的工作项，登记依赖和负责人。
5. **实现与自测**：实现者先运行最小相关测试。
6. **代码评审**：至少一名同领域工程师评审；协议或安全变更需安全参与。
7. **QA 验证**：按验收条件测试并记录证据。
8. **产品验收**：PM 和设计师核对行为、文案和视觉。
9. **合并与回归**：进入主分支前跑自动化，候选版本跑完整回归。
10. **发布与复盘**：记录指标、问题和下一版本决策。

## 6. 会议和沟通节奏

小团队保持轻量：

- 每日 10 分钟站会：完成、计划、阻塞。
- 每周两次设计/技术评审：只讨论待决策项。
- 每个闸门一次验收会议，会议前异步阅读材料。
- Beta 每两天汇总一次用户反馈，不实时改变已冻结范围。
- 决策写入 ADR 或对应文档，不依赖聊天记录。

## 7. 风险登记

| ID | 风险 | 概率 | 影响 | 负责人 | 缓解 |
|---|---|---:|---:|---|---|
| R-01 | 用户误以为独立原生任务也在实时监控 | 中 | 高 | 产品/设计 | 托管标识、historyOnly 分区、首次启动说明 |
| R-02 | App 退出或崩溃中断 active turn | 中 | 高 | 集成/Swift | 菜单栏常驻、退出确认、重启校准 |
| R-03 | Codex 升级导致协议变化 | 高 | 中 | 集成 | schema、版本门槛、未知字段兼容 |
| R-04 | 审批错配、迟到或被重复提交 | 低 | 极高 | 集成/安全 | 五元组关联、连接代次、幂等和禁用态 |
| R-05 | 卡片拟人化掩盖技术含义 | 中 | 中 | 设计/PM | 双重文案、可用性测试 |
| R-06 | 过度保存任务数据 | 低 | 高 | 安全 | 最小缓存、7 天清理、脱敏测试 |
| R-07 | 菜单栏通知过多 | 中 | 中 | PM/设计 | 聚合、静默时间、项目级设置 |
| R-08 | 自定义字体增加包体或授权风险 | 低 | 中 | 设计/发布 | 许可证审查、可回退字体方案 |
| R-09 | App Sandbox 限制子进程或 socket | 中 | 中 | Swift/发布 | 首期直接分发；G0 后决定签名策略 |

## 8. 决策权限

- PM 可调整文案、排序和非技术范围。
- 技术负责人可拒绝依赖私有接口或扩大 App Server 权限面的方案。
- 安全负责人可阻断写调用、审批和敏感数据变更。
- QA 可因 P0/P1 或不可复现的核心状态阻断发布。
- 发布负责人可因签名、公证、许可证或回滚缺失阻断发布。

## 9. 变更控制

以下变更必须更新文档并重新评审：

- 增加长期权限、自动审批或新的任务控制方法。
- 改变“只有工作台托管任务才实时”的所有权边界。
- 引入私有 Codex IPC 或 transcript 解析。
- 开放网络端口、远程连接或云端同步。
- 保存完整命令、对话、diff 或凭据。
- 提高最低 macOS 版本或改变分发方式。

## 10. 下一版本候选

v1.1 优先考虑：

1. `acceptForSession` 等长期权限能力的独立安全设计。
2. `turn/steer`、fork、批量中断和高级任务编排。
3. 官方共享 daemon 或原生客户端实时互通（仅在公开支持后）。

只有 v1.0 真实用户数据证明这两项能显著减少经理处理时间时才进入开发。
